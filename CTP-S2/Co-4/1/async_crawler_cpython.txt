Question 1: Design a High-Throughput Web Crawler Using Asyncio (CPython Execution)

#1.Definition: In CPython (the standard reference implementation of Python), a high-throughput web crawler leverages the single-threaded event loop (asyncio). 
Although CPython uses a Global Interpreter Lock (GIL) which restricts multi-threading for CPU-bound code, 
I/O-bound operations (like network requests) release the GIL during system calls (such as select or epoll). 
This allows CPython to cooperatively switch between thousands of concurrent network tasks on a single OS thread without blocking.

#2.Algorithm
Define Async Fetch Task: Create an asynchronous function (fetch_page) that accepts a URL and a delay, simulates a network request using await asyncio.sleep(), and yields control back to the event loop.

Define Main Function: Set up a list of target URLs with simulated download delays.

Schedule Concurrent Tasks: Wrap the fetch calls into a list of tasks for all URLs.

Gather Results: Use asyncio.gather() to execute all tasks concurrently on CPython's event loop rather than running them one-by-one.

Execute Event Loop: Run the main asynchronous function using asyncio.run().

#3.Pseudocode
Plaintext
ASYNC FUNCTION fetch_page(url: String, delay: Float) -> String
    PRINT "Starting request to: " + url
    AWAIT async_sleep(delay)  // Releases control back to CPython event loop
    PRINT "Finished request to: " + url
    RETURN "Response content from " + url
END FUNCTION

ASYNC FUNCTION main()
    SET urls_with_delays = [(URL1, 1.5), (URL2, 0.5), (URL3, 1.0)]
    
    // Create concurrent tasks
    SET tasks = [fetch_page(url, delay) FOR EACH (url, delay) IN urls_with_delays]
    
    // Run all tasks concurrently
    SET results = AWAIT asyncio.gather(tasks)
    
    PRINT results
END FUNCTION

// Entry point
RUN asyncio.run(main())

#4.explanation
I designed this high-throughput crawler using Python's asyncio library to perform non-blocking, cooperative multitasking on CPython's single-threaded event loop.

Here is how the components work together:

The Async Worker (fetch_page): I defined fetch_page as an asynchronous coroutine using async def. When it hits await asyncio.sleep(delay), it simulates a network request. Crucially, the await keyword tells CPython to pause this specific task and release execution control back to the event loop so other tasks can run.

Concurrent Task Packaging (asyncio.gather): In the main function, instead of running my URL requests sequentially (which would block execution), I create a list of tasks and pass them to asyncio.gather(*tasks). This schedules all of them to execute concurrently within CPython's event loop.

Performance and Efficiency: You can see from the output that the total execution time is 1.50 seconds—the exact duration of the longest delay—rather than 3.0 seconds. This proves that CPython managed the network simulations concurrently on a single thread without blocking or wasting CPU cycles."
